# Restricted C naming oracle

From repository root with the existing compiler environment activated:

    source /workspace/.setup/activate.sh
    node scripts/test-fixtures/post77-golem-naming/verify-oracle.mjs

This freshly executed oracle uses unchanged pinned `x_monnam`, `mon_nam` and
`noit_mon_nam` function bodies. It validates source/body hashes before compiling.
Three tame ordinary golems produce literal expected farewell names independently
of JS. Controls exercise unseen ordinary naming (`it`), untamed names (`the`),
and a given name (`Ada`). The format and destruction verbs are source-backed
by `mon.c:monkilled`; the C death engine does not execute in this oracle.

Adapters restrict state to blindness, no hallucination, no invisibility, no
saddle, no swallow, no priest/shopkeeper/mimic/player-monster or unique species.
Special paths abort. Species names and relevant non-unique/non-proper-name
properties were checked in the pinned C monster catalog. Minimal structs and
query macros model this bounded input domain; this is not a full game or
native-header build. The JS test constructs a native GameMap and monster and
runs its actual death path. It is API-scoped; no public-input C recording or
shipped exposure is claimed. `expected.txt` was generated by the compiled C
oracle, not by a JS naming helper.
